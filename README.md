# Agent Address

Agent Address is an identity and address registry for independent AI Agents and their conversation Sessions.

It answers **which Agent/Session identity exists**, **which Organization owns it**, and **who is authorized to use it**. Agent Address does not deliver messages, store conversation transcripts, run AI models, or transfer files. Messaging services such as Nuwa Agent Relay can depend on its addresses.

## Identity model

Every canonical address has exactly three segments:

```text
organization/agent/session
nuwa/codex-win-a7k2/ffl-dev
nuwa/xiaoming/main
```

- **Organization:** an account's authorized identity scope.
- **Agent:** an independent identity, not a program, model, machine, or runtime.
- **Session:** a conversation/work context belonging to an Agent.
- **Runtime:** the executing process or installation, separate from the address.

One program can host many Agents. One Agent can have one or many Sessions. Each Agent has a default Session; an address containing only `organization/agent` resolves to it. Names may be provided for either segment or generated by the server.

A Session can have only one active Runtime owner. Resume requires the private `resumeToken` and is rejected while another Runtime's renewable lease is active. The caller may create a new Agent/Session instead. Resume credentials and runtime credentials are separate. Runtime leases expire after 15 minutes unless renewed. The MCP Ensure operation renews or securely restores its existing Session as needed; explicit lifecycle tools remain available.

See [Identity architecture](docs/identity-architecture.md) for terminology, invariants and design details.

## Architecture

```text
                    Cloudflare Worker
                ┌─────────────────────┐
OAuth login ────►│ /authorize          │
MCP tools ──────►│ /mcp                │
HTTP clients ───►│ /v2/account/*       │
Admin browser ──►│ /admin/ + /admin/api│
Portal browser ─►│ /portal/            │
                ├─────────────────────┤
                │ IdentityController  │
                │ Domain services     │
                └──────────┬──────────┘
                           │
                        D1 database
```

The MCP adapter is a client of the same `IdentityController` used by the HTTP API. The shared service layer knows nothing about HTTP, MCP, Cloudflare Access or UI components.

Human MCP users sign in through the OAuth authorization-code flow at `/authorize`, with email/password and a sign-up registration key when configured. Accounts register their Organization separately; one account owns at most one Organization in the current identity model.

## Account HTTP API

All Account API routes require an OAuth access token: `Authorization: Bearer <token>`.

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/v2/account/status` | Signed-in account and Organization |
| POST | `/v2/account/organization` | Register the account's Organization (`slug`, `displayName`) |
| PATCH | `/v2/account/organization` | Change Organization display name |
| GET | `/v2/account/agents` | List Organization Agents |
| POST | `/v2/account/agents` | Register Agent and Default Session without occupying a Runtime |
| POST | `/v2/account/agents/claim` | Create Agent and Default Session with an active Runtime lease |
| PATCH | `/v2/account/agents/{agentID}` | Update Agent handle or display name |
| DELETE | `/v2/account/agents/{agentID}` | Archive Agent, all Sessions and their Runtime leases |
| GET | `/v2/account/agents/{agentID}/sessions` | List Agent Sessions |
| POST | `/v2/account/agents/{agentID}/sessions` | Register another Session without occupying a Runtime |
| POST | `/v2/account/agents/{agentID}/sessions/claim` | Create another Session and acquire a Runtime lease |
| PATCH | `/v2/account/sessions/{sessionID}` | Update Session handle or display name |
| PUT | `/v2/account/sessions/{sessionID}/default` | Set Agent's Default Session |
| DELETE | `/v2/account/sessions/{sessionID}` | Archive a non-default Session and revoke its Runtime lease |
| POST | `/v2/account/sessions/{sessionID}/rotate-resume` | Replace a lost Resume Token without changing the active Runtime |
| GET | `/v2/account/sessions/{sessionID}` | Read Session identity |
| POST | `/v2/account/sessions/{sessionID}/resume` | Resume with `resumeToken`, when unoccupied |
| POST | `/v2/account/sessions/{sessionID}/heartbeat` | Renew active Runtime with `runtimeToken` |
| POST | `/v2/account/sessions/{sessionID}/release` | Release a Runtime's ownership |
| GET | `/v2/account/resolve?address=...` | Resolve Agent shorthand or full canonical address |

A new Agent request can specify `agentName`, `sessionName`, `agentDisplayName`, `sessionDisplayName`, and optional `runtimeLabel`. Omitted handles are generated. Registration returns a private `resumeToken` without claiming a Runtime. Claiming also returns a `runtimeToken` and lease expiration. These capabilities are issued once; store them privately. They are capabilities, not human-readable addresses.

For a new Codex doing FFL development, only `sessionName: "ffl-dev"` is necessary. For a multi-Agent bot, only `agentName: "xiaoming"` is necessary; its Default Session is automatically named `main`. Both return a full `organization/agent/session` address.

## MCP tools

Connect an OAuth-capable MCP client to `/mcp`. The intended first-use experience is **OAuth login → one automatic `agentAddressEnsureIdentity` tool call → a complete canonical address**. The Agent follows its Skill without asking the user for an address, Session ID, Runtime Token or Resume Token.

- `agentAddressEnsureIdentity`: automatically create a private personal Organization if none exists, Claim a new Agent with Default Session, or restore the Session already held by this MCP connection. The Agent persona may supply an optional display name such as `小晴`. A valid ASCII handle is generated by the identity service.
- `agentAddressGetStatus`: inspect the current authenticated Account, Organization and Session; `agentAddressListAgents`, `agentAddressListSessions`, `agentAddressResolve`: directory and address lookup.
- `agentAddressClaimAgent`, `agentAddressCreateSession`, `agentAddressRegisterOrganization`: explicit changes on the user's request, not normal installation chores.
- `agentAddressResumeSession`: resume **only** the Session whose private Resume credential is already retained by this MCP connection; no token input.
- `agentAddressHeartbeatRuntime`, `agentAddressReleaseRuntime`, `agentAddressForgetLocalSession`: advanced lifecycle controls. Releasing a Runtime does not delete the saved address or its private Resume credential.

MCP invokes the same HTTP identity domain services used by other Account API clients. Runtime/Resume capabilities are saved privately in Durable Object storage and **never exposed in a model-facing MCP argument or result**. Existing independent MCP connections remain separate Agents even if they use the same human OAuth Account.

Restoring a Session after the original MCP storage is lost requires a trusted, separately authenticated recovery channel. Knowing an address, persona name or Organization membership is **not** proof of ownership, and automatic recovery must never take over another active Runtime. A provider's re-created MCP connection must preserve its trusted connection state to guarantee the same address after restart; this is an integration acceptance requirement, not an excuse to ask the user for tokens.

The no-question bootstrap assumes the user is authorized to create a personal Organization when one does not exist. Existing Organization membership is reused. To join a shared Organization or change the current address, use the explicit Organization Portal process.

## Administration

`/admin/` is an internal administrator UI protected by Cloudflare Access. Its API is `/admin/api/*`, also behind the same Access application, and independently validates the Access JWT.

Administrators can inspect Account/Organization/Agent/Session metadata and reset account passwords. Resetting an account password invalidates previous OAuth grants. The internal Admin UI does not expose resume or runtime tokens.

The Organization self-service UI is available at `/portal/`. It signs in through the same OAuth flow as MCP and calls the same `/v2/account/*` API. It registers, lists and edits Organizations, Agents and Sessions; changes Default Sessions; archives identities; shows non-sensitive Runtime availability; and can rotate Resume Tokens. Registration never claims a Runtime. The administrator console remains a separate Cloudflare Access-protected surface.

## Testing and deployment

Use the project Testing Guide and [CODE_PRINCIPLES.md](CODE_PRINCIPLES.md). Exercise real Worker routing, OAuth and D1 through scenario-based tests; do not mock internal business behavior. The admin UI has a browser test, and the Organization Portal has a real-Chromium test that drives a local Worker, OAuth, and D1 without internal API mocks.

```bash
npm ci
npm run check
npm run style:check
npm test
npm --prefix web ci
npm --prefix web run build
```

Cloudflare Workers, Durable Objects, OAuth KV, and D1 are deployed together by GitHub Actions only after the checks pass. The workflow applies D1 migrations before publishing a Worker.

**Deployment:** push to GitHub `main` to run the original `.github/workflows/deploy.yml` verification and automatic release. It uses existing GitHub Repository Secrets and Variables, resolves the canonical Cloudflare resources named `company-notes-agent-address` (D1) and `OAUTH_KV` (KV) by exact name, rejects mixed legacy database schemas, then publishes the official `agent-address` Worker. See [Operations](docs/Operations.md) for resource identities, release steps, production testing and unrelated Releasebot cleanup candidates.

**Registration:** OAuth sign-up requires entering a password twice. Client-side form validation and server-side checks both reject a mismatch. This is password confirmation, not second-factor authentication.
