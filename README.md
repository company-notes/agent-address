# Agent Address

Agent Address is an identity and address registry for independent AI Agents and their conversation Sessions.

It answers **which Agent/Session identity exists**, **which Organization owns it**, and **who is authorized to use it**. Agent Address does not deliver messages, store conversation transcripts, run AI models, or transfer files. Messaging services such as Nuwa Agent Relay can depend on its addresses.

## Identity model

Every canonical address has exactly three segments:

```text
organization/agent/session
nuwa/codex-win-a7k2/ffl-dev
nuwa/xiaoming/main
```

- **Organization:** an account's authorized identity scope.
- **Agent:** an independent identity, not a program, model, machine, or runtime.
- **Session:** a conversation/work context belonging to an Agent.
- **Runtime:** the executing process or installation, separate from the address.

One program can host many Agents. One Agent can have one or many Sessions. Each Agent has a default Session; an address containing only `organization/agent` resolves to it. Names may be provided for either segment or generated by the server.

A Session can have only one active Runtime owner. Resume requires the private `resumeToken` and is rejected while another Runtime's renewable lease is active. The caller may create a new Agent/Session instead. Resume credentials and runtime credentials are separate.

See [Identity architecture](docs/identity-architecture.md) for terminology, invariants and design details.

## Architecture

```text
                    Cloudflare Worker
                ┌─────────────────────┐
OAuth login ────►│ /authorize          │
MCP tools ──────►│ /mcp                │
HTTP clients ───►│ /v2/account/*       │
Admin browser ──►│ /admin/ + /admin/api│
Portal browser ─►│ /portal/            │
                ├─────────────────────┤
                │ IdentityController  │
                │ Domain services     │
                └──────────┬──────────┘
                           │
                        D1 database
```

The MCP adapter is a client of the same `IdentityController` used by the HTTP API. The shared service layer knows nothing about HTTP, MCP, Cloudflare Access or UI components.

Human MCP users sign in through the OAuth authorization-code flow at `/authorize`, with email/password and a sign-up registration key when configured. Accounts register their Organization separately; one account owns at most one Organization in the current identity model.

## Account HTTP API

All Account API routes require an OAuth access token: `Authorization: Bearer <token>`.

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/v2/account/status` | Signed-in account and Organization |
| POST | `/v2/account/organization` | Register the account's Organization (`slug`, `displayName`) |
| GET | `/v2/account/agents` | List Organization Agents |
| POST | `/v2/account/agents` | Register Agent and Default Session without occupying a Runtime |
| POST | `/v2/account/agents/claim` | Create Agent and Default Session with an active Runtime lease |
| GET | `/v2/account/agents/{agentID}/sessions` | List Agent Sessions |
| POST | `/v2/account/agents/{agentID}/sessions` | Register another Session without occupying a Runtime |
| POST | `/v2/account/agents/{agentID}/sessions/claim` | Create another Session and acquire a Runtime lease |
| GET | `/v2/account/sessions/{sessionID}` | Read Session identity |
| POST | `/v2/account/sessions/{sessionID}/resume` | Resume with `resumeToken`, when unoccupied |
| POST | `/v2/account/sessions/{sessionID}/heartbeat` | Renew active Runtime with `runtimeToken` |
| POST | `/v2/account/sessions/{sessionID}/release` | Release a Runtime's ownership |
| GET | `/v2/account/resolve?address=...` | Resolve Agent shorthand or full canonical address |

A new Agent request can specify `agentName`, `sessionName`, `agentDisplayName`, `sessionDisplayName`, and optional `runtimeLabel`. Omitted handles are generated. Registration returns a private `resumeToken` without claiming a Runtime. Claiming also returns a `runtimeToken` and lease expiration. These capabilities are issued once; store them privately. They are capabilities, not human-readable addresses.

For a new Codex doing FFL development, only `sessionName: "ffl-dev"` is necessary. For a multi-Agent bot, only `agentName: "xiaoming"` is necessary. Both return a full `organization/agent/session` address.

## MCP tools

Connect an OAuth-capable MCP client to `/mcp`. Available tools:

- `agentAddressGetStatus` and `agentAddressRegisterOrganization`
- `agentAddressClaimAgent` and `agentAddressCreateSession`
- `agentAddressResumeSession` and `agentAddressReleaseRuntime`
- `agentAddressListAgents`, `agentAddressListSessions`, `agentAddressResolve`

MCP uses exactly the same HTTP controller and domain rules as other Account API clients. The current MCP connection remembers its active Session in Durable Object storage.

## Administration

`/admin/` is an internal administrator UI protected by Cloudflare Access. Its API is `/admin/api/*`, also behind the same Access application, and independently validates the Access JWT.

Administrators can inspect Account/Organization/Agent/Session metadata and reset account passwords. Resetting an account password invalidates previous OAuth grants. The internal Admin UI does not expose resume or runtime tokens.

The Organization self-service UI is available at `/portal/`. It signs in through the same OAuth flow as MCP and calls the same `/v2/account/*` API. It can register and list Agents and Sessions without pretending a browser is an active Runtime. The administrator console remains a separate Cloudflare Access-protected surface.

## Testing and deployment

Use the project Testing Guide and [CODE_PRINCIPLES.md](CODE_PRINCIPLES.md). Exercise real Worker routing, OAuth and D1 through scenario-based tests; do not mock internal business behavior. The admin UI has a browser test, and the Organization Portal has a real-Chromium test that drives a local Worker, OAuth, and D1 without internal API mocks.

```bash
npm ci
npm run check
npm run style:check
npm test
npm --prefix web ci
npm --prefix web run build
```

Cloudflare Workers, Durable Objects, OAuth KV, and D1 are deployed together by GitHub Actions only after the checks pass. The workflow applies D1 migrations before publishing a Worker.

**Database cutover:** `migrations/0001_identity.sql` is the clean new-schema baseline for an isolated D1 database. Do not apply it to the previously deployed Host/Work database: it has different tables and migration history. Configure a separate test database and verify the full flow before authorizing any production database switch. Never delete existing D1 data implicitly during code refactoring.
